# Naming proposal and clearance

Date screened: 2026-10-13. This is a limited naming screen, not a trademark clearance, domain-availability check or guarantee of uniqueness.

## Recommended working name: Daynori

Pronunciation: **day-nor-ee**. Seven ASCII letters, one word.

Proposed brand meaning: a coined combination of **day** with a sound associated with **organize** and **origin**: one place from which to organize an ordinary day. This is an invented brand association, not a claimed dictionary translation or cultural etymology.

Working tagline: **Your day, together.** Alternative descriptive line for research: **A home for your everyday life.** Keep shared-rooms messaging separate; the tagline must not imply that personal content is automatically shared.

The name can cover notes, routines, files and reflection without naming one module. Validate pronunciation and spelling with Bangla and English speakers. The final identity should use a simple wordmark and an abstract folded-page/home motif; avoid logos suggesting a medical, banking or password-manager certification.

## Search screen and rejected candidates

Queries included quoted exact names, the name with `app`, and exact-name index searches restricted to `play.google.com` and `apps.apple.com`. Search engines are incomplete and results change. No clear software/app collision appeared for Daynori in this limited screen; unrelated personal names, dictionary-index and historical references did appear. This is only a reason to continue investigating.

- **Dayvora:** rejected because existing products use it for birthdays/reminders and daily finance. Primary examples: [StakhivLabs product](https://stakhivlabs.com/dayvora), [App Store listing](https://apps.apple.com/us/app/dayvora/id6806296586) and [Dayvora finance site](https://www.dayvora.app/).
- **Daylume:** rejected because existing planner and journal products use it. Primary examples: [Daylume planner](https://daylume.ai/) and [Daylume journal](https://daylume.io/).
- **Daynest:** rejected because existing planning and memory products use it. Primary examples: [Google Play planner listing](https://play.google.com/store/apps/details?id=com.farazinc.daynest) and [developer memory app page](https://younatics.github.io/apps/daynest/).
- **Dailora:** rejected because existing habit/task apps use it. Primary example: [Google Play habit app](https://play.google.com/store/apps/details?id=com.lxt.dailora).
- **Dayweft:** rejected because existing mobile products use it. Primary example: [DayWeft product](https://dayweft.com/).
- **Daylivo:** deprioritized because the name is already used by websites/consumer products. Primary example: [Daylivo site](https://daylivo.online/). No inference about that site's reputation is needed for this decision.

Do not buy a domain, publish store metadata or choose immutable production identifiers from this screen alone.

## Clearance gate before public branding

1. Confirm the intended owner, launch countries and product/service categories.
2. Search relevant official trademark registries and phonetic/spelling variants; obtain qualified legal review if preparing a commercial launch.
3. Check Google Play and Apple App Store directly in intended markets, not only search-engine indexes.
4. Check company names, ordinary web usage, GitHub/package namespace collision and common social handles.
5. Check domain availability through a registrar and approve a purchase budget; record the actual registration result instead of assuming `.com` or `.app` is free.
6. Test pronunciation, spelling recall and unintended meanings with prospective users. Screen the logo separately.
7. Record the accepted name and evidence in a decision record; only then freeze application IDs, sender names, store listing and branded assets.

Until that gate passes, use Daynori as editable display copy and keep repository/domain contracts brand-independent. If a conflict appears, replace the display name consistently through one documented phase.
