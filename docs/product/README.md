# Product planning

Status: proposed baseline for Phase 00. No application behavior is implemented yet.

Read these documents in order:

1. [Product brief](product-brief.md) explains the audience, promise, scope and release boundaries.
2. [Requirements and acceptance criteria](requirements.md) defines stable requirement IDs for phase plans and tests.
3. [Naming decision](naming.md) records the provisional name and clearance work.
4. [Information architecture](../design/information-architecture.md) defines navigation and organization.
5. [Journeys and onboarding](../design/journeys.md) defines common flows and recoverable failures.
6. [Design system direction](../design/design-system.md) defines the proposed visual language.
7. [Accessibility and design validation](../design/accessibility.md) defines evidence needed before release.

Requirement IDs are stable across future phases. A phase must cite the IDs it completes and add its own implementation checklist, evidence and remaining limitations. A future agent can change a proposal through a documented decision; it must not silently expand release scope.
